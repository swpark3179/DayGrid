# TestFlight 기기 확인 체크리스트

시뮬레이터와 UI 테스트로 확인하기 어려운 항목을 실제 iPhone에서 확인한다. 위에서부터 순서대로 따라 하면 된다.
Phase 4·5·6·8에서 미룬 기기 확인을 모았다(`docs/ROADMAP.md`의 "나중에 할 테스트").

- 준비
  - `main` 브랜치에서 `.github/workflows/testflight.yml`을 수동 실행한다(방법은 `docs/TESTFLIGHT.md`).
  - 처리가 끝나면 iPhone의 TestFlight 앱에서 새 빌드를 설치한다.
- 결과 기록: 문제가 있으면 항목 번호, 기대한 동작, 실제 동작을 적어 둔다. 화면 녹화가 있으면 더 좋다.

## 1. 설치와 기존 데이터
- [ ] 1-1. 이전 빌드 위에 업데이트해도 앱이 바로 열린다.
- [ ] 1-2. 이전 빌드에서 만든 일정, 할일, 카테고리가 그대로 남아 있다.
- [ ] 1-3. 처음 실행할 때 알림 권한이나 연락처 권한을 묻지 않는다. 권한은 그 기능을 처음 쓸 때만 묻는다.

## 2. 나중에 할일 (Phase 4)
- [ ] 2-1. "나중에" 탭의 빠른 입력창에서 엔터를 칠 때마다 항목이 들어가고, 키보드가 내려가지 않아 이어서 쓸 수 있다.
- [ ] 2-2. 빈 채로 엔터를 치면 입력을 마친다.
- [ ] 2-3. 행을 왼쪽으로 밀면 날짜·삭제가, 오른쪽으로 밀면 완료가 나오고, 각각 동작한다.
- [ ] 2-4. "편집"을 누르고 행을 끌어 순서를 바꾼다. 앱을 껐다 켜도 순서가 그대로다.
- [ ] 2-5. 날짜 정하기 시트에서 오늘·내일·이번 주말과 시간을 고르면 달력에 그 날로 들어간다.
- [ ] 2-6. 하루 상세에서 행을 오른쪽으로 밀어 "나중에"를 누르면 "나중에" 탭 맨 위로 돌아온다. 다시 날짜를 정할 때 이전 모양(종일/시간, 길이)이 기본값으로 나온다.
- [ ] 2-7. 홈 화면에서 앱 아이콘을 길게 누르면 "할일 빠르게 추가"가 보이고, 누르면 입력창에 바로 쓸 수 있다.
  - 앱을 한 번 실행한 뒤부터 보인다(코드로 등록하는 항목).
  - 앱이 떠 있을 때와 완전히 꺼져 있을 때 둘 다 확인한다.

## 3. 본문 (Phase 5)
- [ ] 3-1. 일정 편집 → 본문 → 편집에서 키보드 위 서식 툴바가 보인다.
- [ ] 3-2. 툴바의 굵게, 기울임, 목록, 체크리스트, 링크, 인용, 코드, 제목이 선택 영역에 맞게 들어간다. 같은 버튼을 다시 누르면 벗겨진다.
- [ ] 3-3. 툴바로 바꾼 내용을 흔들기 또는 세 손가락 쓸기로 실행 취소할 수 있다.
- [ ] 3-4. 미리보기에서 표, 체크리스트, HTML 태그가 그려진다. `<script>`는 실행되지 않는다.
- [ ] 3-5. 미리보기의 링크를 누르면 앱 안이 아니라 Safari에서 열린다.
- [ ] 3-6. 다크 모드로 바꾸면 미리보기 글자와 배경도 어둡게 바뀐다.
- [ ] 3-7. 비행기 모드에서도 미리보기가 그려진다(오프라인).
- [ ] 3-8. 목록 행에 본문 아이콘과 첫 줄 미리보기가 보인다.

## 4. 공휴일, 개인 휴일, 생일 (Phase 6)
- [ ] 4-1. 달력에서 공휴일과 대체공휴일이 빨간 숫자와 이름으로 보인다(예: 2026년 10월 3일 개천절, 5일 대체공휴일, 9일 한글날).
- [ ] 4-2. 설정 → 개인 휴일에서 기간을 만들면 달력에 빨갛게 보인다.
- [ ] 4-3. 설정 → 생일 → 연락처에서 가져오기
  - 처음 누를 때만 연락처 권한을 묻는다.
  - "일부 연락처만 허용"(iOS 18)을 고르면, 고른 연락처의 생일만 들어온다.
  - 연락처에 음력 생일이 있으면 음력으로 들어오고, 달력에는 올해 양력 날짜에 🎂가 보인다.
  - 다시 가져오면 같은 사람이 둘로 늘지 않고, 연락처에서 바꾼 생일이 반영된다.
  - 권한을 거부하면 설정 앱에서 허용하라는 안내가 나온다.
- [ ] 4-4. 30일 안에 생일이 있으면 달력 위에 배너가 보이고, 누르면 생일 목록이 열린다.
- [ ] 4-5. 공휴일 보정 파일 원격 갱신(선택)
  - `DayGrid/Resources/holidays/KR-overrides.json`에 시험용 항목을 넣고 `version`을 올려 main에 머지한다.
  - 다음 날 앱을 열면 그 날짜가 휴일로 보인다(하루에 한 번까지만 받아 온다). 확인한 뒤 시험용 항목을 지우고 `version`을 다시 올린다.

## 5. 반복 할일 (Phase 7)
- [ ] 5-1. 반복 탭에서 매일, 매주(여러 요일), 매월(n일, 말일) 할일을 만든다.
- [ ] 5-2. 체크하면 달력의 그 날에 ✓가 보이고, 다시 누르면 취소된다.
- [ ] 5-3. 하루가 지나면 어제 체크하지 않은 매일 할일이 "놓침"으로 보인다.

## 6. 알림 (Phase 8)
시각을 맞춰 기다려야 하는 항목이 많다. 6-2부터는 지금부터 15분쯤 뒤의 시간 일정을 만들어 확인하면 빠르다.
- [ ] 6-1. 권한 요청 시점
  - 일정 편집에서 알림을 처음 켤 때만 권한을 묻는다.
  - 설정의 생일 알림이나 반복 할일 알림을 처음 켤 때도 같다.
  - 거부한 뒤에는 다시 묻지 않는다. 설정의 "시스템 알림 설정 열기"로 허용할 수 있다.
- [ ] 6-2. 시간 일정: "정시"와 "10분 전"을 켜면 두 번 온다. 내용에 시작 시각이 보인다.
- [ ] 6-3. 종일 일정: "당일 오전 9시", "전날 오전 9시"가 그 시각에 온다.
- [ ] 6-4. 생일: 설정 → 알림 → 생일 알림을 "당일, 1일 전"으로 두면 생일 전날과 당일 오전 9시에 온다.
- [ ] 6-5. 반복 할일: 알림을 켜면 주기가 시작되는 날 정한 시각에 한 번만 온다. 이미 체크한 주기는 오지 않는다.
- [ ] 6-6. "완료" 동작
  - 할일 알림을 길게 눌러 "완료"를 누르면, 앱을 열지 않아도 그 할일이 완료된다.
  - 반복 할일 알림에서 누르면 그 주기가 체크된다.
- [ ] 6-7. 알림을 누르면 앱이 열리고 그 날의 하루 상세가 보인다.
- [ ] 6-8. 앱을 쓰는 중에도 알림 배너가 보인다.
- [ ] 6-9. 일정을 지우거나 시각을 바꾸면 예전 알림이 오지 않는다.
- [ ] 6-10. 백그라운드 새로 고침(며칠 두고 확인)
  - 앱을 며칠 열지 않아도, 30일 뒤에 있던 일정의 알림이 때가 되면 온다.
  - 하루 한 번 백그라운드 새로 고침이 대기 알림을 다시 채우는지 보는 항목이다. iOS가 실행 시점을 정하므로 늦을 수 있다.
